Graph：先畫好流程，錯在哪關退回哪關

Loop 由 AI 決定下一步，Graph 的流程是你事先畫好的。

是什麼？差別在「誰在控制」

🔁 Loop

像自己反覆改作業，改到檢查表全部通過。AI 決定下一步。

🕸️ Graph

像學校的申請流程：系辦 → 院 → 教務處，不能跳關，卡住會退回特定一關。流程是你事先畫好的。

其實三種都是圖

做法畫成圖的樣子
Prompt一個節點，跑一次
Loop多一條「回到自己」的邊
GraphA → B → C，退回的邊可以接到任何一個節點

順利跑完的 graph，其實就是一條流水線。

好的 graph：大圈很少轉，小圈轉得很快

檢索 → 大綱 → 逐頁稿 → 渲染 → 交件

  • 小圈：錯了就在附近修，很快。
  • 大圈：從最後一關退回起點，應該很少發生。
設計原則

錯誤要在離源頭最近的地方被抓到。如果常常在轉大圈，代表檢查應該往前移。

每一格裡面還是 loop：graph 決定大流程，loop 負責每一格裡的反覆修正。

該用哪一種？

  1. 先用 Prompt一次性的工作，而且你自己會看。
  2. 升級成 Loop你發現自己一直重複說同樣的修正。
  3. 拆成 Graphloop 每次都整份重來，或各階段的標準不一樣。
PromptLoopGraph
流程誰決定你，即時決定AI，在規格內決定你，事先畫好
出錯怎麼修你發現、你下指令整份再跑一輪退回出錯的那一關
人在哪裡介入隨時最後驗收指定關卡
適合一次性、自己看標準明確的重複任務多階段、多人使用

讓問題本身告訴你需要多少結構，不一定要堅持用 graph。

重點回顧

  • Loop 由 AI 決定下一步，Graph 的流程由你事先畫好
  • Prompt、Loop、Graph 都可以畫成圖，差別在邊怎麼接
  • 好的 graph 在離源頭最近的地方抓錯
  • 從 Prompt 開始，需要時才升級成 Loop 或 Graph
