案例第 10 週

主題 → HTML 簡報的三種做法

同一個任務，用 Prompt、Loop、Graph 做會有什麼不同。

任務

你說一個主題（例如多模態 RAG），AI 只用 wiki 的內容做出一份 HTML 簡報。同一個 wiki、同一個模型、同一件事，只換做法。

做法一：Prompt（一句話）

「根據 wiki 裡關於多模態 RAG 的內容，做一份 HTML 簡報。」AI 回你「做好了！」，然後你開始一直修：

  • 😵 第 5 頁字太多，跑出畫面
  • 🔍 這個 37% 是哪篇論文的？
  • 📚 8 篇相關論文只用了 3 篇
  • 🔄 論文 A 的結論講反了
其實這裡也有 loop

只是你自己就是那個 loop。

做法二：Loop（把修正寫成 SKILL.md）

項目內容
🎯 目標只用 wiki，產出 HTML 簡報
✅ 程式檢查每頁有出處、引用頁面存在、數字找得到、8～15 頁、渲染後沒有溢出
🧑‍⚖️ AI 審查開新對話，只給簡報和引用頁，檢查忠實度和覆蓋率
🔁 每一輪只修檢查報告列出的問題
🛑 停止全部通過、改滿 3 輪，或一開始發現相關頁面少於 3 頁就停下
  1. 第 1 輪腳本：3 頁溢出、2 處沒出處；審查：第 6 頁講反了。
  2. 第 2 輪腳本全過；審查：論文 D 沒用到。
  3. 第 3 輪補進論文 D，全部通過，交件時附上檢查報告。

你只要最後看報告就好。

做法三：Graph（先畫好流程）

檢索 → 證據卡 → 大綱 → 逐頁稿 → 渲染 → 交件

中間設了覆蓋率關卡（資料不足就停）、人工確認大綱、忠實度檢查、渲染檢查。每一關能看什麼、不能做什麼都事先規定好：

節點只能看不能做
證據卡一篇論文混入其他來源
逐頁稿大綱＋對應卡片引用卡片以外的內容
渲染 HTML已通過的逐頁稿改任何一個字
檢查關卡成品＋來源自己動手改

錯在哪一關，就退回哪一關

  • 📄 第 6 頁講錯：只修那一頁，其他 14 頁不動
  • 🃏 卡片本身錯：退回重抽那一篇的證據卡
  • ✂️ 字太多：不是硬塞，退回逐頁稿縮短
  • 🧩 缺子題：人看大綱時發現，退回檢索補資料
狀態都是檔案

sources.md、cards/、outline.md、drafts/、deck.html、report.md。每一關的產出都能打開來看、放進 git、單獨重跑。流程可以寫成 workflow 檔放進 .agents/workflows/，再用 /topic-slides 呼叫；每一道檢查關卡就是一支腳本。

重點回顧

  • Prompt 版：你自己變成那個 loop
  • Loop 版：把你的修正寫成規格，最後只看報告
  • Graph 版：每關限定能看與能改的範圍，錯在哪關退回哪關
  • 中間產物都存成檔案，方便檢查和重跑
